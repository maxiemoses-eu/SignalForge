Why we chose a three repository GitOps topology for SignalForge and how we navigated our first deployment hurdles

When we sat down to design SignalForge, we knew we did not want a traditional monolithic structure or even a standard single repository microservices setup. We chose a three repository topology, dividing our ecosystem into application source code, infrastructure as code using Terraform, and GitOps deployments managed by ArgoCD and Helm. This separation of concerns ensures that our application developers, platform engineers, and operations teams can work completely independently without stepping on each other. Our microservices are built using a polyglot approach, matching each service to the most efficient language for its job, which is why we ended up with Nodejs, Go, Java, and Python running side by side.

With our services defined, we set out to build a security first deployment pipeline using GitHub Actions. We integrated GitLeaks to scan for accidental secrets, Hadolint to check our Dockerfiles, and Trivy to scan final container layers for critical vulnerabilities. But our first attempt to push verified container images to the GitHub Container Registry was met with immediate failure.

The registry was rejecting our push requests due to invalid tag formats. We quickly realized that the registry enforces a strict lowercase rule for all repository owners and image names. Because our repository contains uppercase letters, our container tags were automatically flagged as invalid. To fix this without introducing bloated external actions, we injected standard bash parameter expansion in a simple runner step to dynamically lowercase our owner and repository variables. This kept our pipeline fast, clean, and completely native. 

Now that our secure container builds are passing and pushing seamlessly, we are shifting our focus to telemetry and observability. Every step of this journey has shown us that building a secure microservices ecosystem is less about avoiding errors and more about resolving them with simple, elegant engineering decisions.
